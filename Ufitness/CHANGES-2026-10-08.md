## Part D - security, moderation, checks, offline sync (8 Oct 2026)

### 4. Security review
- Audited `supabase/schema.sql`. Fixes are in `supabase/migrations/2026-10-08-security.sql` (safe to re-run; also appended to `schema.sql`):
  - **Anon access removed.** Supabase gives the `anon` role EXECUTE on every function and ALL on every table by default.
    `list_students()` had no sign-in check, so the public anon key could list every student card. Now anon can run no
    `public` function and read no `public` table; only the app's RPCs are granted to signed-in users, and `list_students()`
    also checks `auth.uid()`.
  - `is_campus_admin()` now needs a **confirmed** email.
  - Display names in `group_members`, `mentor_requests` (and `chat_reports`, see 6) are filled from `profiles` by triggers,
    so a student can't post under someone else's name.
  - All policies are `to authenticated`; profiles have no delete policy (account removal goes through `delete_own_account()`).
  - `search_path` pinned on the last two functions without it; group name/description length check.
  - Storage: the app uses no buckets, so nothing to add (noted in SECURITY.md).
- **LoyaltyHub key moved off the client.** New Edge Function `supabase/functions/loyaltyhub-proxy/index.ts` (Deno):
  reads the `LOYALTYHUB_KEY` secret, refuses requests without a real signed-in user, and only allows the two calls the app
  makes (`prices` search, `products` by barcode).
  - `src/features/meals/lib/loyaltyHub.js` calls it with `supabase.functions.invoke`. If the function isn't deployed yet
    (404/503) or you're signed out/offline, it falls back to the old direct call (only while the old key is still in `.env`),
    then to estimated prices, like before. Pure rules in `loyaltyProxyRules.js` (tested).
  - `.env.example` no longer lists the key. Deploy steps: `DEPLOY-EDGE-FUNCTION.md`. `supabase/SECURITY.md` has the full findings table.
- **Secret scan** of `src/`, `scripts/`, app config and `supabase/`: no hard-coded keys, tokens or passwords. `.env` is git-ignored.
  `EXPO_PUBLIC_RAPIDAPI_KEY` is still read on the client (listed as a known gap).

### 6. Moderation workflow
- SQL: `supabase/migrations/2026-10-08-moderation.sql` (safe to re-run; appended to `schema.sql` after the security part).
  - `chat_reports` gets `status` (open / resolved / dismissed), `resolved_by`, `resolved_at`. A trigger makes every new
    report yours and open, and fills the reported name from the profile.
  - Admin-only RPCs: `admin_resolve_report`, `admin_delete_message` (group or direct message; resolves its open reports),
    `admin_set_suspended`. Every action is logged in `moderation_actions` (admin-only read).
  - `profiles.suspended` (+ reason, time) can only change through the admin RPC (trigger). RLS stops suspended students
    from inserting `group_messages`, `direct_messages` and the community doc (`user_docs` `communityState`). Other saves
    (meals, workouts) still work, and they can still report.
- App:
  - Admin dashboard - Reports: open reports first, status chip, **Resolve / Dismiss / Reopen**, **Delete message**,
    **Suspend user / Lift suspension** (tap twice to confirm), "Show handled reports" toggle, Open reports KPI
    (`src/features/admin/components/ReportCard.js`, rules in `src/lib/moderationRules.js`).
  - Suspended students see **"Your account is suspended"** (`src/screens/auth/SuspendedScreen.js`) with *Check again* and
    *Sign out*. Checked at sign-in and whenever the app comes back to the foreground.
  - Profile - Privacy & Security - **Blocked users** (`src/screens/profile/BlockedUsersScreen.js`): people you blocked in
    chat plus feed-post names blocked on this phone, each with **Unblock**.

## Part E - Downloads for offline use (8 Oct 2026)

### Where Downloads lives
- **Profile - App - Downloads**, plus a **download icon in the Home header** (next to the bell) that opens the same screen.
- Not a 6th tab: the tab bar already has 5 slots with the raised orange Workout button in the middle. A 6th icon makes
  each tab about 54 px wide on a 320 px phone and squeezes the labels. Downloads is something you open now and then,
  so a header icon and a Profile row fit better.

### What can be downloaded ("Download for offline" - "Downloaded -" + Remove)
- **Workout session or program** (Workout - Programs - a session/program): exercise list, sets/reps/rest, how-to text,
  exercise GIFs/photos saved as files, and the program's clip thumbnails (YouTube clips themselves can't be saved).
  Offline, the Exercises screen, exercise detail, How-to and the Player use the downloaded copy and the saved pictures.
- **Weekly meal plan** (Meals - Plan): the week's meals, swaps, custom plates, the grocery list and the food catalog
  with prices, plus meal photos.
- **Single recipe** (open a meal): the meal, its ingredient names/prices and photo. A cook video that is a direct file
  link (mp4) is saved and plays offline; YouTube videos save their thumbnail and show "YouTube videos need internet".
- **Grocery list** (Meals - Shop - Grocery list): items, store, cadence and prices, plus the generated **PDF** (phone).

### How it works
- `src/lib/downloads/downloadsCore.js` (pure, tested): index, size per item, total storage (a picture shared by two
  workouts counts once), sections, "Downloaded on 8 Oct 2026", the offline fallback choice
  (`pickOfflineSource`: live / download / old fallback), and which media links each kind saves.
- `src/lib/downloads/downloadsStore.js`: index in AsyncStorage, files in `documentDirectory/downloads/` (`media/`, `pdf/`)
  via `expo-file-system` (installed with `npx expo install`). Delete one / delete all. Media files are shared between
  downloads and only deleted when nothing uses them. `useLocalMedia(url)` returns the saved file when there is one;
  used in ExerciseGif (Player, exercise detail, How-to), the exercise list rows, MealDetail and CookVideo.
- **Downloads screen** (`src/screens/profile/DownloadsScreen.js`): storage used, sections (Workouts, Meal plans,
  Recipes, Grocery lists), size + date per item, delete one, "Delete all" (tap twice), "Open PDF" for lists,
  an offline banner (NetInfo) and an empty state. Tapping an item opens it in its normal screen:
  workouts in Workout - Exercises, plans/lists in Meals (shown as a read-only "Downloaded copy" with a "My plan" button
  back), recipes in the recipe sheet.
- **Offline-first:** no connection - the Exercises screen uses the downloaded session/program straight away;
  the Meals tab uses the newest downloaded plan's foods and prices instead of the built-in estimates.
- **Web:** only the JSON is saved (no files). The button and the Downloads screen say "Videos download on the phone app".
- Deleting the account also deletes all downloads.

## Part F - AI Coach (8 Oct 2026)
Cloud LLM coach for UJ students (Gemini via Vercel AI SDK in a Supabase Edge Function).

### How it works
- App: Home - **AI Coach** card (also Profile stack - `AiCoach`). Chat UI with quick-prompt chips (`Plan my week on R300`, `Workout for today`, `What should I eat after gym?`-). Chat history is saved on this phone per student (`ufitness.coach.v1.<uid>`). Offline shows the yellow banner; the coach needs internet.
- Edge Function `supabase/functions/ai-coach/`: verifies the student's JWT, counts the message against **30/day** (`ai_coach_take()`), then asks Gemini (`gemini-2.5-flash`) with the Vercel AI SDK (`ai` + `@ai-sdk/google`). The Gemini key is the `GEMINI_API_KEY` secret - never in the app or `.env`.
- Read-only tools (RLS, student's own JWT): `get_my_profile`, `get_my_workouts`, `get_my_meal_plan`, `get_my_progress`, `propose_plan` (structured plan card the app renders). Safety: not a doctor, budget-aware (rand), Campus Health / SADAG for crises.
- States the screen handles: not set up (404/503), rate limit (429), offline, auth, busy, generic error (via `cloudErrors`).
